# CRM مخاطبین

پنل مدیریت اطلاعات مخاطبین با **ثبت کامل سابقه تغییرات هر فیلد** (Django).

## امکانات
- فیلدهای اصلی: نام، نام خانوادگی، نام پدر، کد ملی (با اعتبارسنجی رقم کنترل)، شماره تماس، شماره دوم، شماره پدر، آیدی تلگرام / اینستاگرام / توییتر / بله، کد پستی، آدرس، یادداشت.
- **فیلدهای اضافه نامحدود**: از منوی «انواع فیلد اضافه» هر فیلد جدیدی (ایمیل، واتساپ، ایتا، شغل، …) را تعریف کنید و برای هر مخاطب پر کنید.
- **لاگ تغییرات**: هر ایجاد/ویرایش/حذف هر فیلد با مقدار قبلی، مقدار جدید، کاربر و زمان (شمسی) ذخیره می‌شود. لاگ‌ها غیرقابل ویرایش‌اند و بعد از حذف مخاطب هم باقی می‌مانند.
- **وضعیت پرونده در هر تاریخ**: در صفحه مخاطب، «وضعیت پرونده در یک تاریخ دلخواه» نشان می‌دهد هر فیلد در آن تاریخ (مثلاً `1405/07/09 14:30`) چه مقداری داشته.
- تاریخچه هر فیلد به‌تنهایی (کلیک روی نام فیلد در جدول تغییرات).
- نرمال‌سازی ورودی: اعداد فارسی، `+98`/`0098`، خط تیره و فاصله در شماره‌ها؛ `@user` یا لینک پروفایل در آیدی‌ها.
- جستجو در همه فیلدها (حتی با اعداد فارسی یا فرمت `+98`)، خروجی CSV سازگار با اکسل.
- چندکاربره با سطح دسترسی (کاربران و گروه‌های جنگو).

## اجرا
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```
سپس به `http://127.0.0.1:8000/admin/` بروید.

تست‌ها: `python manage.py test crm`

## تنظیمات محیط (برای سرور)
| متغیر | توضیح |
|---|---|
| `DJANGO_SECRET_KEY` | کلید مخفی (حتماً تنظیم شود) |
| `DJANGO_DEBUG` | `0` در محیط واقعی |
| `DJANGO_ALLOWED_HOSTS` | دامنه‌ها، جداشده با کاما |
| `CRM_DB_PATH` | مسیر فایل دیتابیس SQLite |

> این داده‌ها شخصی و حساس‌اند: پنل را فقط پشت HTTPS اجرا کنید، از دیتابیس بکاپ رمزنگاری‌شده بگیرید و دسترسی کاربران را محدود کنید.

## مرحله بعد: اتصال SIP ترانک
شماره‌ها به فرمت یکسان (`09121234567`) ذخیره می‌شوند تا مستقیم قابل شماره‌گیری باشند. برنامه پیشنهادی:
Asterisk/Issabel و اتصال از طریق AMI/ARI ← دکمه «تماس» روی هر شماره (click-to-call)، ثبت تماس‌های ورودی/خروجی در پرونده مخاطب، و باز شدن خودکار پرونده هنگام تماس ورودی (caller ID lookup).
