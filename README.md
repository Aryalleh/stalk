# کادوچی + CRM (یک Cloudflare Worker)

یک Worker با یک دیتابیس D1 و یک باکت R2:

| مسیر | چیست |
|---|---|
| `/` | سایت عمومی خرید کادو از لیست آرزو |
| `/panel` | پنل فروشگاه‌ها |
| `/admin` | مدیریت پلتفرم (تأیید فروشگاه‌ها، آمار فروش، **تنظیمات سایت**) |
| `/crm` | CRM داخلی مخاطبین — فقط مدیر و کاربرانی که دسترسی CRM دارند |

حساب کاربری برای همه یکی است (ورود با موبایل و رمز). مدیر پلتفرم از `/crm/users` به هر کاربر دسترسی CRM می‌دهد.

> نام سایت («کادوچی» پیش‌فرض) از `/admin/settings` عوض می‌شود.

## فروشگاه کادو

1. **فروشگاه** ثبت‌نام می‌کند ← مدیر تأیید می‌کند ← فروشگاه محصول (با عکس) و **شماره کارتش** را ثبت می‌کند.
2. **کاربر** لیست آرزو می‌سازد (با آدرس ارسال محرمانه)، محصولات را با تعداد و یادداشت اضافه می‌کند و لینک لیست را می‌فرستد.
3. **خریدار** (بدون ثبت‌نام) یک آرزو را انتخاب می‌کند ← شماره کارت فروشگاه و مبلغ را می‌بیند؛ آرزو ۳۰ دقیقه برایش رزرو می‌شود ←
   کارت به کارت می‌کند و شماره پیگیری، ۴ رقم آخر کارت و (اختیاری) عکس رسید را ثبت می‌کند. لینک خصوصی سفارش را برای پیگیری وضعیت نگه می‌دارد.
4. **برای فروشگاه در بله/تلگرام پیام می‌رود**: «واریز اعلام شد، حساب را چک و در پنل تأیید کنید».
5. فروشگاه حسابش را بررسی می‌کند و **تأیید** یا **رد** می‌زند.
   - تأیید ← آدرس گیرنده نمایش داده می‌شود و پیام «این کادو را برای این گیرنده ارسال کن» هم در بات می‌آید.
   - رد ← خریدار دلیل را در صفحه سفارشش می‌بیند و آرزو دوباره قابل خرید می‌شود.
6. فروشگاه کد رهگیری ثبت می‌کند؛ صاحب لیست کادوها، پیام‌های تبریک و کد رهگیری را می‌بیند.

نکات:
- آدرس گیرنده هیچ‌وقت به خریدار نشان داده نمی‌شود و فروشگاه هم فقط بعد از تأیید واریز آن را می‌بیند.
- دو نفر هم‌زمان یک آرزو را نمی‌خرند: رزرو با یک INSERT اتمی است و واریزهای اعلام‌شده تا تأیید/رد فروشگاه جا را نگه می‌دارند.
- عکس رسیدها خصوصی‌اند و فقط از پنل همان فروشگاه باز می‌شوند. شماره کارت با الگوریتم Luhn بررسی می‌شود.
- پول مستقیم به کارت فروشگاه می‌رود؛ پلتفرم کمیسیونی برنمی‌دارد و تسویه‌ای لازم نیست.

## CRM (`/crm`)

مخاطبین با فیلدهای اصلی (نام، نام پدر، کد ملی، شماره‌ها، آیدی تلگرام/اینستاگرام/توییتر/بله، کد پستی، آدرس) و فیلدهای اضافه دلخواه.
هر تغییر هر فیلد با مقدار قبلی/جدید، کاربر و زمان شمسی ثبت می‌شود و می‌شود وضعیت پرونده را در هر تاریخ دید.

## بله: ورود با کد و پیام رایگان از طریق بات

**ورود/ثبت‌نام با کد یکبار مصرف (سفیر بله):** وقتی «سفیر» در تنظیمات فعال باشد، در صفحه ورود دکمه «ورود یا ثبت‌نام با کد یکبار مصرف بله»
می‌آید. کد ۶ رقمی با سرویس OTP سفیر به بله کاربر می‌رود؛ اگر حساب ندارد همان‌جا با نامش ساخته می‌شود (بدون رمز).
کد ۵ دقیقه اعتبار دارد، فقط یک‌بار و با حداکثر ۵ تلاش؛ ارسال دوباره بعد از ۶۰ ثانیه و حداکثر ۵ بار در ساعت. فقط hash کد ذخیره می‌شود.

**وصل کردن شماره‌ها به بات (پیام رایگان):**
1. لینک دعوت `https://ble.ir/<بات>?start=link` (در `/admin/settings` و صفحه هر مخاطب CRM) را برای افراد بفرستید.
2. فرد در بات دکمه «📱 اشتراک شماره من» را می‌زند؛ بله شماره **خود او** را می‌فرستد (شماره فورواردی دیگران پذیرفته نمی‌شود) و شماره به شناسه چتش وصل می‌شود.
3. در CRM کنار هر شماره وصل‌شده «✓ وصل به بات» نمایش داده می‌شود و از صفحه مخاطب **پیام رایگان با بات** می‌فرستید.
   به شماره‌های وصل‌نشده می‌توانید از طریق **سفیر (هزینه‌دار)** پیام بدهید. همه پیام‌ها با وضعیت و فرستنده در صفحه مخاطب ثبت می‌شوند.
4. اگر صاحب فروشگاه شماره‌اش را به بات وصل کرده باشد، پیام سفارش‌ها خودکار برایش می‌رود (حتی اگر شناسه چت را در پنل وارد نکرده باشد).

تنظیمات (در `/admin/settings`): کلید API سفیر (`api-access-key` از پنل کسب‌وکار بله) و شناسه عددی بازو (`bot_id`)، به‌علاوه توکن بات بله و دکمه «اتصال».

## راه‌اندازی روی Cloudflare
```bash
npm install
npx wrangler login
npx wrangler d1 create app                    # database_id را در wrangler.jsonc بگذارید
npx wrangler r2 bucket create gift-shop-images
npm run deploy
```
جدول‌های دیتابیس را خود Worker در اولین درخواست بعد از هر دیپلوی به‌روز می‌کند (`src/migrate.ts`)؛ اجرای دستی
`npm run db:migrate:remote` لازم نیست ولی ضرری هم ندارد. migration جدید: فایل را در `migrations/` بسازید و در `src/migrate.ts` اضافه کنید
(تست بررسی می‌کند چیزی جا نیفتاده باشد).
هیچ secret یا متغیری لازم نیست. بعد از دیپلوی:
1. **فوراً** `/setup` را باز کنید و مدیر پلتفرم را بسازید (اولین کسی که این فرم را پر کند مدیر می‌شود؛ بعد صفحه بسته می‌شود).
2. در **`/admin/settings`** همه تنظیمات از داخل سایت عوض می‌شود:
   - نام سایت، آدرس سایت (برای لینک‌های داخل پیام‌های بات)، مهلت واریز خریدار
   - توکن بات بله و تلگرام ← دکمه «اتصال» توکن را بررسی و webhook را خودکار تنظیم می‌کند (روی https).
   توکن‌ها بعد از ذخیره فقط به صورت `••••abcd` نمایش داده می‌شوند.
3. برای CRM می‌توانید Cloudflare Access را فقط روی مسیر `/crm*` بگذارید تا یک لایه امنیتی دیگر داشته باشد.

بکاپ: `npx wrangler d1 export app --remote --output backup.sql`

## اجرای محلی
```bash
npm install
npm run dev                                   # http://localhost:8787 ← /setup
```
تست‌ها: `npm test` — بررسی تایپ: `npm run typecheck`

## ساختار
| مسیر | کار |
|---|---|
| `src/index.tsx` | ورودی Worker؛ سایت روی `/` و CRM روی `/crm` |
| `src/session.ts`, `src/settings.ts` | حساب کاربری مشترک؛ تنظیمات سایت (در D1، قابل ویرایش از وب) |
| `src/bale/` | سفیر (OTP و پیام به شماره)، کد ورود، اتصال شماره‌ها، webhook بات |
| `src/shop/` | فروشگاه: `db.ts` (رزرو/تأیید واریز)، `notify.ts` (بله/تلگرام)، `routes/`، `views/` |
| `src/crm/` | CRM: `db.ts` (ذخیره + لاگ در یک تراکنش)، `history.ts` (وضعیت در تاریخ)، `fields.ts`، `views/` |
| `lib/` | رمز و نشست، تاریخ شمسی، نرمال‌سازی شماره/کارت |
| `migrations/` | جدول‌های D1 |

## قدم‌های بعدی پیشنهادی
- خرید گروهی (چند نفر روی یک کادوی گران سهم بگذارند).
- اتصال SIP ترانک به CRM (نیاز به سرور Asterisk/Issabel کنار Worker).
- محدودیت تعداد تلاش ورود (rate limit).
