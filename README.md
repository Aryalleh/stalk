# CRM مخاطبین (Cloudflare Worker + D1)

پنل مدیریت اطلاعات مخاطبین با **ثبت کامل سابقه تغییرات هر فیلد**، روی Cloudflare Workers و دیتابیس D1.

## امکانات
- فیلدهای اصلی: نام، نام خانوادگی، نام پدر، کد ملی (با اعتبارسنجی رقم کنترل و جلوگیری از تکرار)، شماره تماس، شماره دوم، شماره پدر، آیدی تلگرام / اینستاگرام / توییتر / بله، کد پستی، آدرس، یادداشت.
- **فیلدهای اضافه نامحدود**: در صفحه «فیلدهای اضافه» هر فیلد جدیدی (ایمیل، واتساپ، شغل، …) تعریف کنید تا در فرم همه مخاطبین ظاهر شود.
- **لاگ تغییرات**: هر ایجاد/ویرایش/حذف هر فیلد با مقدار قبلی، مقدار جدید، کاربر و زمان (شمسی، به وقت تهران) ثبت می‌شود. لاگ قابل ویرایش نیست و بعد از حذف مخاطب هم باقی می‌ماند.
- **وضعیت پرونده در هر تاریخ**: در صفحه مخاطب ← «وضعیت پرونده در یک تاریخ دلخواه»، مثلاً `1405/07/09 14:30`.
- تاریخچه هر فیلد به‌تنهایی (کلیک روی نام فیلد در جدول تغییرات).
- نرمال‌سازی ورودی: اعداد فارسی، `+98`/`0098`، خط تیره و فاصله در شماره‌ها؛ `@user` یا لینک پروفایل در آیدی‌ها.
- جستجو در همه فیلدها (با اعداد فارسی یا `+98` هم پیدا می‌کند)، خروجی CSV سازگار با اکسل.
- چندکاربره: مدیر کاربر می‌سازد؛ رمزها با PBKDF2 هش می‌شوند؛ محافظت CSRF.

## راه‌اندازی روی Cloudflare
```bash
npm install
npx wrangler login
npx wrangler d1 create crm          # database_id خروجی را در wrangler.jsonc بگذارید
npm run db:migrate:remote
npx wrangler secret put SETUP_TOKEN # یک رمز طولانی تصادفی
npm run deploy
```
سپس آدرس Worker را باز کنید؛ چون هنوز کاربری نیست به `/setup` می‌روید. با `SETUP_TOKEN` اولین مدیر را بسازید. بعد از ساخت اولین کاربر، صفحه setup خودکار غیرفعال می‌شود.

## اجرای محلی
```bash
npm install
echo 'SETUP_TOKEN="local-token"' > .dev.vars
npm run db:migrate:local
npm run dev                          # http://localhost:8787
```
تست‌ها: `npm test` — بررسی تایپ: `npm run typecheck`

## ساختار
| فایل | کار |
|---|---|
| `migrations/0001_init.sql` | جدول‌ها: users, sessions, contacts, field_definitions, extra_values, change_log |
| `src/index.tsx` | مسیرها (Hono) |
| `src/db.ts` | ذخیره/حذف مخاطب + نوشتن لاگ در یک تراکنش، جستجو |
| `src/history.ts` | محاسبه تغییرات و بازسازی وضعیت در یک تاریخ |
| `src/fields.ts` | تعریف فیلدهای اصلی (برای افزودن فیلد اصلی جدید: اینجا + یک migration) |
| `lib/` | تاریخ شمسی، نرمال‌سازی، رمز و نشست (مشترک با shop) |
| `src/views/` | صفحات (JSX، راست‌به‌چپ) |

> این داده‌ها شخصی و حساس‌اند. دسترسی را محدود نگه دارید؛ برای لایه امنیتی بیشتر می‌توانید Cloudflare Access را جلوی Worker بگذارید. بکاپ: `npx wrangler d1 export crm --remote --output backup.sql`

## مرحله بعد: SIP ترانک
Worker خودش نمی‌تواند SIP/RTP برقرار کند؛ یک سرور Asterisk/Issabel لازم است. معماری پیشنهادی:
- **تماس خروجی (click-to-call)**: دکمه تماس در CRM ← Worker درخواست را به API کوچکی روی سرور Asterisk (ARI/AMI) می‌فرستد.
- **تماس ورودی**: Asterisk شماره تماس‌گیرنده را به یک endpoint در Worker می‌فرستد ← پرونده مخاطب پیدا و تماس ثبت می‌شود.
- شماره‌ها از الان با فرمت یکسان (`09121234567`) ذخیره می‌شوند تا مستقیم قابل جستجو و شماره‌گیری باشند.
